1.1

What you are actually being asked to do

Why

Before any code: get the shape of the problem in your head. You will explain this in the introduction of your report and if it's vague there, it's vague everywhere.

There are 96 units — think of them as 96 separate machines or sites, named unit_000 to unit_095. For each one you have 4,320 consecutive hourly readings, running from 2023-01-01 00:00 to 2023-06-29 23:00. That's 180 days.

At each hour you get 22 numbers describing conditions (demand_forecast, staffing_forecast, hour-of-day, and so on) and one number you care about: target, the operational load index.

The task: for each of the 96 units, predict target for the next 336 hours (14 days) after the training data ends. That's 96 × 336 = 32,256 numbers in your submission CSV.

What "336-step horizon" really costs you

Predicting one hour ahead is easy — the answer is close to the last value you saw. Predicting 336 hours ahead means the last observed value is two weeks stale and nearly useless. All your signal has to come from repeating patterns (this unit is always busy at 6pm on weekdays) and from the covariates. That's why the seasonal-mean baseline is respectable and why beating it takes real work.

Map the missing values

Why

Ten of the 22 feature columns contain gaps. This is deliberate on the instructors' part — handling them is part of the task. PyTorch will happily train on NaN and produce a loss of nan forever, so you must deal with this before any model runs.

▸notebooks/01_eda.ipynb · cell 4python

# are gaps isolated hours, or long stretches?

What to do about them — and this is an ablation

Three strategies, in increasing sophistication:

  1. Forward-fill then zero-fill. Carry the last known value forward within each series; anything still missing at the very start becomes 0. Simple, sensible, and your default.
  2. Fill with the feature mean. Slightly worse usually, but a fair comparison point.
  3. Fill + a mask channel. For each gappy column, add a second column that is 1 where the value was missing. The model learns "this reading is fabricated, trust it less." Doubles those channels but often helps.

Run all three later and put them in Table 2. Free ablation, real finding.

Forward-fill across series boundaries

df.ffill() on the whole frame will carry unit_000's last value into unit_001's first row. Always df.groupby("series_id")[cols].ffill(). This bug is invisible — no error, just slightly poisoned data.

1.7

Find the trend trap

Why

trend is a normalised clock — it counts hours since the start of the dataset, rescaled. Across all 4,992 hours it runs from about −1.73 to +1.73. But train.csv stops at hour 4,320, where trend is only about +1.27. Every value it takes during the test period is one your model has never seen.

print(tr.trend.min(), tr.trend.max())
print(tr.groupby("series_id").trend.mean().std())  # ~0 -> identical across units

Neural networks are bad at extrapolating beyond their training range. If the model learns "when trend is high, load is high," it has no idea what to do at trend = 1.5. It might produce anything.

What to do

Don't delete it silently — ablate it. Run your best model with and without trend and report both numbers. If dropping it helps, you have a finding worth a paragraph, and it demonstrates you understand distribution shift. That is exactly the kind of thing that separates a 1.7 from a 2.3.

2.2

Implement the metrics

Why

The leaderboard reports six numbers and WAPE is the primary one. You need all six locally so your table matches theirs, and you need to understand what WAPE is so you can pick a loss function that actually optimises it (step 4.3).

WAPE is the sum of your absolute errors divided by the sum of the true values:

WAPE = Σ|y − ŷ| / Σ|y|

Read that again: the numerator is just total absolute error. WAPE is MAE with a fixed rescaling. That single observation drives your loss choice later — anything that minimises MAE minimises WAPE.

▸src/metrics.pypython
import numpy as np

def _prep(y, p):
    y = np.asarray(y, dtype=np.float64).ravel()
    p = np.asarray(p, dtype=np.float64).ravel()
    assert y.shape == p.shape, f"shape mismatch {y.shape} vs {p.shape}"
    assert np.isfinite(p).all(), "predictions contain NaN or inf"
    return y, p

def mae(y, p):   y,p=_prep(y,p); return np.abs(y-p).mean()
def mse(y, p):   y,p=_prep(y,p); return ((y-p)**2).mean()
def rmse(y, p):  return np.sqrt(mse(y,p))

def wape(y, p):
    y,p = _prep(y,p)
    return np.abs(y-p).sum() / np.abs(y).sum()

def mape(y, p, eps=1e-8):
    y,p = _prep(y,p)
    return (np.abs(y-p) / np.maximum(np.abs(y), eps)).mean()

def smape(y, p, eps=1e-8):
    y,p = _prep(y,p)
    denom = np.maximum((np.abs(y)+np.abs(p))/2, eps)
    return (np.abs(y-p) / denom).mean()

def all_metrics(y, p):
    return {"wape": wape(y,p), "mae": mae(y,p), "rmse": rmse(y,p),
            "mse": mse(y,p), "mape": mape(y,p), "smape": smape(y,p)}
The two asserts are not decoration

Shape mismatch and NaN predictions are the two failure modes that produce a plausible-looking number that is completely wrong. Crashing loudly is much better than a silently good WAPE.

Worth a paragraph in your report

WAPE divides by the total of all true values, so big-load units dominate it. MAPE divides each error by its own true value, so small-load units dominate that. These two metrics can disagree about which model is better, and when they do, saying why shows you understand your own evaluation.

2.3

Build the rolling-origin split

Why

One 336-hour holdout is a sample of size one. If two models differ by 2% on it, you genuinely cannot tell whether that's a real improvement or the particular fortnight you happened to pick. N_TRAIN_HOURS = 4320

def fold_bounds(fold: int, total: int = N_TRAIN_HOURS, h: int = H):
    """Return (train_end, score_start, score_end) as hour indices."""
    score_end   = total - fold * h
    score_start = score_end - h
    train_end   = score_start   # training must not touch [score_start, score_end)
    return train_end, score_start, score_end
The leak that will get you

Your training windows must end before train_end. A window of lookback L that predicts hours [t, t+336) is only legal if t + 336 <= train_end. If you allow windows whose targets reach into the scoring region, your validation score will look wonderful and mean nothing. Write this as an assertion in your dataset class, not a comment.

How much data does this leave?

With lookback L = 512, one sample spans 512 + 336 = 848 hours. Fold 0 gives 3984 − 848 + 1 = 3,137 start positions per unit × 96 units = 301,152 training windows. That is plenty; you are not data-starved.

3.1

Understand what one training sample is

Why

If you can draw a single sample on paper you can debug the whole pipeline. If you can't, you'll spend days confused by shape errors.

One sample is a pair: a window of the past and the 336 hours that followed it. Both come from the same unit.

pick a unit, pick a start hour t:

  X = features and target for hours [t, t+L)        <- what the model sees
  Y = target only,      for hours [t+L, t+L+336)    <- what it must predict

with L = 512:
  X shape: (512, 22 features + 1 target) = (512, 23)
  Y shape: (336,)

Every legal value of t for every unit gives you another sample. That is why a 180-day dataset yields 300,000 training examples — the windows overlap heavily.

Why include past target inside X

The target's own history is the strongest predictor you have. A model that only sees the covariates is throwing away the fact that this unit ran at load 22 for the last three days. Include it as just another input channel.

3.2

Why

Slicing windows out of a pandas DataFrame inside a training loop is slow — you'd spend more time in pandas than in the model. Convert once into a NumPy array shaped (96 units, 4320 hours, channels) and all slicing becomes instant array indexing. The whole thing is about 40 MB in float32.

import numpy as np, pandas as pd, torch

STATIC  = ["nominal_capacity","zone_sin","zone_cos"]

def load_cube(path, use_trend=True, fill="ffill", add_mask=False):
    """long CSV -> (X, Y, series_ids, hours, feat_names, static)

    X : (S, T, F) float32   dynamic features, scaled later
    Y : (S, T)    float32   target
    """
    df = pd.read_csv(path, parse_dates=["timestamp"])
    df = df.sort_values(["series_id","timestamp"]).reset_index(drop=True)

    series = sorted(df.series_id.unique())          # FIXED order, save it
    hours  = np.sort(df.timestamp.unique())
    S, T   = len(series), len(hours)

    feats = [c for c in df.columns
             if c not in ("series_id","timestamp","target") + tuple(STATIC)]
    if not use_trend: feats = [c for c in feats if c != "trend"]

    gappy = [c for c in feats if df[c].isna().any()]
    if add_mask:
        for c in gappy:
            df[c + "_isna"] = df[c].isna().astype("float32")
        feats += [c + "_isna" for c in gappy]

    # fill INSIDE each series -- never across the boundary
    if fill == "ffill":
        df[gappy] = df.groupby("series_id")[gappy].ffill()
        df[gappy] = df.groupby("series_id")[gappy].bfill()
    elif fill == "mean":
        df[gappy] = df[gappy].fillna(df[gappy].mean())
    df[gappy] = df[gappy].fillna(0.0)

    X = df[feats].to_numpy("float32").reshape(S, T, len(feats))
    Y = df["target"].to_numpy("float32").reshape(S, T)
    St = df.groupby("series_id")[STATIC].first().loc[series].to_numpy("float32")

    assert np.isfinite(X).all() and np.isfinite(Y).all()
    return X, Y, series, hours, feats, St

3.3

Scale the features — and save the numbers

Why

Feature values range from 0–1 up to 0–86. Networks initialise assuming inputs are roughly mean 0, std 1; wildly different scales make some weights dominate and training unstable. So you standardise: subtract the mean, divide by the standard deviation.

The mean and std must be computed on training hours only. Using statistics that include the scored period is leakage — the model gets a hint about the future.

▸src/scaling.pypython
import numpy as np, torch, torch.nn as nn

class GlobalScaler:
    """Per-feature standardisation. Fit on training hours only."""
    def fit(self, X, upto):                    # X (S,T,F)
        flat = X[:, :upto, :].reshape(-1, X.shape[2])
        self.mean = flat.mean(0)
        self.std  = flat.std(0) + 1e-6
        return self
    def transform(self, X):  return (X - self.mean) / self.std
    def state(self):        return {"mean": self.mean.tolist(), "std": self.std.tolist()}
    @staticmethod
    def from_state(d):
        s = GlobalScaler(); s.mean = np.array(d["mean"], "float32")
        s.std = np.array(d["std"], "float32"); return s


class RevIN(nn.Module):
    """Reversible instance normalisation (Kim et al., ICLR 2022).

    Normalise each window by ITS OWN mean/std, predict, then undo it.
    Handles both scale differences between units and drift over time.
    """
    def __init__(self, eps=1e-5):
        super().__init__(); self.eps = eps; self.mu = None; self.sd = None

    def norm(self, x):                      # x (B, L) or (B, L, C)
        dim = 1
        self.mu = x.mean(dim, keepdim=True)
        self.sd = x.std(dim, keepdim=True) + self.eps
        return (x - self.mu) / self.sd

    def denorm(self, y):                    # y (B, H)
        mu, sd = self.mu, self.sd
        if mu.dim() == 3: mu, sd = mu.squeeze(-1), sd.squeeze(-1)
        return y * sd + mu

from torch.utils.data import Dataset, DataLoader

class WindowDataset(Dataset):
    """Every legal (series, start-hour) pair inside [0, train_end)."""
    def __init__(self, X, Y, L, H, train_end, gap=0):
        self.X, self.Y, self.L, self.H, self.gap = X, Y, L, H, gap
        S = X.shape[0]
        n_starts = train_end - L - gap - H + 1
        assert n_starts > 0, f"L={L}+gap={gap}+H={H} exceeds {train_end} hours"
        self.index = [(s, t) for s in range(S) for t in range(n_starts)]
        self.train_end = train_end

    def __len__(self): return len(self.index)

    def __getitem__(self, i):
        s, t = self.index[i]
        L, H, g = self.L, self.H, self.gap
        assert t + L + g + H <= self.train_end        # no peeking
        f0 = t + L + g                                 # forecast origin
        x_hist = self.X[s, t : t+L]                    # (L, F)
        y_hist = self.Y[s, t : t+L, None]              # (L, 1)
        x_fut  = self.X[s, f0 : f0+H]                  # (H, F) known covariates
        y_fut  = self.Y[s, f0 : f0+H]                  # (H,)   the answer
        return (torch.from_numpy(np.concatenate([x_hist, y_hist], 1)),
                torch.from_numpy(x_fut),
                torch.from_numpy(y_fut),
                s)

def make_loader(ds, bs=64, shuffle=True):
    return DataLoader(ds, batch_size=bs, shuffle=shuffle,
                      num_workers=0, drop_last=shuffle)

4.1

What "training" actually is

Why

You'll write this loop once and reuse it for every model. Understanding the five lines makes every later bug legible.

A model is a big function with adjustable numbers inside (weights). Training is a loop that nudges those numbers until predictions get closer to the truth:

LineWhat happens
pred = model(x)Forward pass. Push the input through and get a guess.
loss = criterion(pred, y)Score it. One number saying how wrong the guess was.
opt.zero_grad()Clear the gradients from last step. PyTorch accumulates by default; forget this and your training is silently wrong.
loss.backward()Backward pass. Work out, for every weight, which direction would reduce the loss.
opt.step()Take a small step in that direction. "Small" is the learning rate.

One pass over all the training data is an epoch. You do several. Between epochs you check performance on the held-out fold — data the model never trained on — and keep the version that scored best.

Read alongside

Géron PyTorch edition, Ch. 10 "Building Neural Networks" for nn.Module and the loop, then Ch. 11 "Training Deep Neural Networks" for optimisers, learning-rate schedules and early stopping. Ch. 11 is what stops your transformer from diverging in Phase 6.

4.2

Choose the loss to match the metric

Why

WAPE = Σ|y−ŷ| / Σ|y|. The denominator is a constant. So minimising mean absolute error minimises WAPE. If you train with MSE — the default everyone reaches for — you are optimising a different thing, one that over-weights rare large errors.

LossPyTorchUse when
L1 / MAEnn.L1Loss()Directly aligned with WAPE. Gradient is constant, which can make the last stretch of training slow.
Hubernn.SmoothL1Loss(beta=1.0)Your default. Behaves like MSE for small errors (smooth gradients) and like L1 for large ones (robust to spikes).
MSEnn.MSELoss()The leaderboard also reports MSE/RMSE. Include as an ablation, not a default.

▸src/models.pypython
import torch, torch.nn as nn
from .scaling import RevIN

class LinearForecaster(nn.Module):
    """Map L past target values straight to H future ones."""
    def __init__(self, L, H, use_revin=True, **_):
        super().__init__()
        self.proj  = nn.Linear(L, H)
        self.revin = RevIN() if use_revin else None

    def forward(self, x_hist, x_fut=None, sidx=None):
        y = x_hist[..., -1]                     # (B, L) target channel is last
        if self.revin: y = self.revin.norm(y)
        out = self.proj(y)                       # (B, H)
        if self.revin: out = self.revin.denorm(out)
        return out

def main():

    ap.add_argument("--model", default="linear")
    ap.add_argument("--fold", type=int, default=0)
    ap.add_argument("--seed", type=int, default=0)
    ap.add_argument("--lookback", type=int, default=512)
    ap.add_argument("--gap", type=int, default=0)      # 0=val protocol, 336=test
    ap.add_argument("--loss", default="huber", choices=list(LOSSES))
    ap.add_argument("--revin", type=int, default=1)
    ap.add_argument("--covariates", type=int, default=0)

    ap.add_argument("--batch-size", type=int, default=64)
    ap.add_argument("--patience", type=int, default=4)
    ap.add_argument("--device", default=None, help="mps | cpu; auto if unset")
    ap.add_argument("--out", default="runs")
    ap.add_argument("--notes", default="")
    a = ap.parse_args()

    torch.manual_seed(a.seed); np.random.seed(a.seed)
    dev, t0 = (a.device or device()), time.time()
    L = a.lookback

        for xh, xf, yf, si in dl:

            opt.zero_grad()

            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)

class LSTMForecaster(nn.Module):
    def __init__(self, L, H, n_feat, d_model=128, layers=2,
                 dropout=0.2, use_revin=True, **_):

                            batch_first=True,

class CovariateHead(nn.Module):
    """Squeeze (B, H, F) known-future covariates into an additive (B, H)."""
    def __init__(self, n_feat, H, d=64, dropout=0.1):
        super().__init__()
        self.point = nn.Sequential(              # per-hour, shared weights
            nn.Linear(n_feat, d), nn.GELU(), nn.Dropout(dropout), nn.Linear(d, 1))
        self.mix = nn.Linear(H, H)               # let hours talk to each other
        nn.init.zeros_(self.mix.weight); nn.init.zeros_(self.mix.bias)

    def forward(self, x_fut):                  # (B, H, F)
        return self.mix(self.point(x_fut).squeeze(-1))   # (B, H)

6.1

Attention, in plain language

Why

You need enough of a mental model to debug shapes and to write two honest paragraphs in Related Work. You do not need to derive anything.

You have a sequence of vectors — call them tokens. Attention lets every token look at every other token and pull in what's relevant. Each token produces three vectors:

  • Query — "here's what I'm looking for"
  • Key — "here's what I contain"
  • Value — "here's what I'd contribute if you picked me"

Compare every query against every key to get a grid of relevance scores, softmax each row so it sums to 1, and use those as weights to average the values. Each token's output is a blend of the whole sequence, weighted by relevance.

Two consequences that matter to you:

  • It costs O(n²). Comparing everything to everything. 512 tokens means 262,144 comparisons per head per layer. This is the problem patching solves.
  • It has no sense of order. Shuffle the tokens and you get the same answer. That's why positional embeddings exist — you add a learned "this is position 7" vector to each token.

Géron PyTorch Ch. 15: Attention Is All You Need, Positional Encodings, Multi-Head Attention. Stop before the BERT/GPT material — it's NLP-specific and won't help you. If it's too dense, read Hands-On Large Language Models Ch. 3 first for the visual version, then come back.

6.2

The two ideas that make PatchTST

Why

Nie et al. (ICLR 2023) contribute two things. You must be able to state both crisply, because your Method section is built on them.

1 · Patching

Instead of treating each hour as a token, chop the series into overlapping chunks and treat each chunk as a token. With patch_len=16 and stride=8:

512 hours  ->  (512 - 16) / 8 + 1  =  63 patches

hours:   [0..15][8..23][16..31] ...        each -> one token
tokens:  512 -> 63           attention cost: 262,144 -> 3,969  (66x cheaper)

Two benefits, not one. The obvious one is cost. The subtler one: a single hour carries almost no meaning, while a 16-hour chunk carries local shape — a morning ramp, an evening peak. Patches are semantically richer tokens.

2 · Channel independence

You have 23 channels (22 features + target). Channel-mixing would let attention run across features. PatchTST instead pushes each channel through the same shared backbone, separately, with no cross-channel attention at all.

(B, C, L)  --reshape-->  (B*C, L)  --backbone-->  (B*C, H)  --reshape-->  (B, C, H)

Counterintuitive, but it works: it multiplies your effective training examples by C and acts as a strong regulariser. Make it an ablation — --channel-mixing 0/1 — and report both.

6.3

Build it

Why

Write your own rather than importing transformers. It's a better Method section, the course expects PyTorch, and you'll be able to debug it. Use the official repo (yuqinie98/PatchTST) as a reference to check yourself against, and say so in the report.

▸src/models.pypython
class PatchTST(nn.Module):
    def __init__(self, L, H, n_feat, patch_len=16, stride=8,
                 d_model=128, layers=3, n_heads=8, d_ff=256,
                 dropout=0.2, use_revin=True, channel_mixing=False,
                 target_only=False, **_):
        super().__init__()
        self.pl, self.st = patch_len, stride
        self.n_patch = (L - patch_len) // stride + 1
        self.C = 1 if target_only else n_feat + 1
        self.mixing, self.target_only = channel_mixing, target_only

        # 1. each patch -> a d_model vector
        self.embed = nn.Linear(patch_len, d_model)
        # 2. learned position per patch
        self.pos   = nn.Parameter(torch.randn(1, self.n_patch, d_model) * 0.02)
        self.drop  = nn.Dropout(dropout)

        enc = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=n_heads, dim_feedforward=d_ff,
            dropout=dropout, activation="gelu",
            batch_first=True, norm_first=True)
        self.backbone = nn.TransformerEncoder(enc, num_layers=layers)

        # 3. flatten all patch vectors -> H predictions
        head_in = self.n_patch * d_model * (self.C if channel_mixing else 1)
        self.head  = nn.Linear(head_in, H)
        self.revin = RevIN() if use_revin else None

    def _patchify(self, z):                       # z (N, L)
        return z.unfold(dimension=1, size=self.pl, step=self.st)  # (N, P, pl)

    def forward(self, x_hist, x_fut=None, sidx=None):
        B, L, _ = x_hist.shape
        x = x_hist[..., -1:] if self.target_only else x_hist
        if self.revin:
            tgt = self.revin.norm(x_hist[..., -1])              # (B, L)
            x = torch.cat([x[..., :-1], tgt.unsqueeze(-1)], -1)

        z = x.permute(0, 2, 1).reshape(B * self.C, L)      # (B*C, L)
        p = self.embed(self._patchify(z)) + self.pos           # (B*C, P, d)
        h = self.backbone(self.drop(p))                        # (B*C, P, d)

        if self.mixing:
            h = h.reshape(B, self.C * self.n_patch * h.size(-1))
            out = self.head(h)                                 # (B, H)
        else:
            out = self.head(h.reshape(B * self.C, -1))         # (B*C, H)
            out = out.reshape(B, self.C, -1)[:, -1]           # target channel

        if self.revin: out = self.revin.denorm(out)
        return out
Three things that will bite
  • norm_first=True. Pre-norm transformers train far more stably than post-norm at this scale. With False you'll likely need a warmup schedule to avoid divergence.
  • batch_first=True. Without it PyTorch expects (seq, batch, feature) and your tensors are silently transposed. Symptom: it trains but predicts nonsense.
  • Channel independence multiplies the effective batch by C. With batch_size=64 and C=23 you're pushing 1,472 sequences per step. If you hit memory pressure, halve the batch size rather than reducing the model.

7.1

What an ablation is

Why

People use the word without explaining it. An ablation is: take your working model, remove or change exactly one component, retrain, measure. The difference is that component's contribution.

It answers the question "did that part actually matter?" — which is the difference between building a model and understanding one. A report saying "we used RevIN, patching, channel independence and covariates, and got WAPE 0.21" tells the examiner nothing. A report saying "RevIN accounts for a 31% WAPE reduction; channel independence for 4%; the covariate head for 12%; patch length made no measurable difference between 8 and 32" tells them you did science.

Negative results are results

"We expected channel independence to help and it did not, at −0.4% ± 1.1%, which is within seed noise" is a perfectly good sentence for a report. It is far better than silence.

def prepare_inference_cube(inp_path, fi, features, series_order, scaler, L, H,
                           fallback_x=None, fallback_y=None, fallback_end=None):
    """Inference tensors. The graded input is covariates-only (no target),
    so the past-target history comes from the baked checkpoint tail."""
    df = pd.read_csv(inp_path, parse_dates=["timestamp"])
    df = df.sort_values(["series_id", "timestamp"])
    S = len(series_order)

    # future covariates -> (S, H, F) in the saved feature order, then scaled
    fut = np.sort(pd.to_datetime(fi.timestamp).unique())[-H:]
    Xf = np.zeros((S, H, len(features)), "float32")
    for i, sid in enumerate(series_order):
        d = df[df.series_id == sid].set_index("timestamp").reindex(fut)
        Xf[i] = d[features].to_numpy("float32")
    Xf = scaler.transform(Xf).astype("float32")

    # history -> (S, L, F+1): baked scaled covariates + baked raw target
    assert fallback_x is not None, ("checkpoint has no baked history; "
        "retrain after step 8.5.2")
    hx = np.asarray(fallback_x, "float32")             # (S, L, F) scaled
    hy = np.asarray(fallback_y, "float32")[..., None]  # (S, L, 1) raw
    Xh = np.concatenate([hx, hy], 2).astype("float32")
    return Xh, Xf, list(series_order)

import argparse, numpy as np, pandas as pd, torch
from pathlib import Path
from src.models import build_model_from_config
from src.scaling import GlobalScaler
from src.data import prepare_inference_cube

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--input_dir", required=True, type=Path)
    ap.add_argument("--output_file", required=True, type=Path)
    ap.add_argument("--checkpoint", required=True, type=Path)
    a = ap.parse_args()

    ck = torch.load(a.checkpoint, map_location="cpu", weights_only=False)
    cfg, L, H = ck["config"], ck["L"], ck["H"]

    # forecast index: test first, validation as fallback
    fi_path = next(p for p in (a.input_dir / "forecast_index_test.csv",
                             a.input_dir / "forecast_index_validation.csv") if p.exists())
    fi = pd.read_csv(fi_path)
    inp = next(p for p in (a.input_dir / "test_input.csv",
                          a.input_dir / "validation_input.csv") if p.exists())

    scaler = GlobalScaler.from_state(ck["scaler"])
    Xh, Xf, series = prepare_inference_cube(
        inp, fi, features=ck["features"], series_order=ck["series"],
        scaler=scaler, L=L, H=H,
        fallback_x=ck.get("history_x"),      # baked-in history:
        fallback_y=ck.get("history_y"),      # used when the input
        fallback_end=ck.get("history_end"))  # has no target column

    model = build_model_from_config(cfg, n_feat=len(ck["features"]),
                                    n_series=len(ck["series"]), L=L, H=H)
    model.load_state_dict(ck["state_dict"]); model.eval()

    with torch.no_grad():
        pred = model(torch.from_numpy(Xh), torch.from_numpy(Xf),
                     torch.arange(len(series))).numpy()          # (S, H)

    # long format, then MERGE onto the index -- never assume row order
    hours = np.sort(pd.to_datetime(fi.timestamp).unique())[-H:]
    out = pd.DataFrame({
        "series_id":  np.repeat(series, H),
        "timestamp":  np.tile(hours, len(series)),
        "prediction": pred.ravel()})

    fi["_ts"] = pd.to_datetime(fi.timestamp)
    final = fi.merge(out.rename(columns={"timestamp": "_ts"}),
                     on=["series_id", "_ts"], how="left")

    assert final.prediction.notna().all(), \
        f"{final.prediction.isna().sum()} rows unfilled"
    assert len(final) == len(fi)

    a.output_file.parent.mkdir(parents=True, exist_ok=True)
    final[["series_id", "timestamp", "prediction"]].to_csv(a.output_file, index=False)
    print("wrote", len(final), "rows")

if __name__ == "__main__":
    main()

Are we beating the baseline? How to check, in plain English

You do not need the leaderboard to know whether a model is good. Everything you need is one command you run on your own laptop. This is the one-screen answer to "how do I test my model, and am I winning?"

First: you are probably already winning — watch the units

WAPE means "how wrong the predictions are." Lower is better. The one thing that trips everyone up: the two places you read it use different scales.

  • The leaderboard writes it as a percentage: 48.10 means 48% wrong.
  • Our own scripts write it as a fraction: 0.30 means 30% wrong.

Same number, times 100. Put them on the same scale and it is obvious:

ModelWAPE (same scale)
naive_last_value (a baseline)~48%
lag24 / lag168 / seasonal baselines~47%
our linear model~30% — clearly better
Rule of thumb

Our scripts print something like 0.30. Multiply by 100 to compare with the leaderboard's 30. A model at 30% error beats a baseline at 48% error — lower always wins.

gap 0 vs gap 336, and offline vs online — the whole thing on one screen

Picture your data as a long line of hourly readings, and the job is to predict the next two weeks.

  • gap 0 — predict the two weeks that start right after your last reading. Easier.
  • gap 336 — predict a two-week window that starts two weeks after your last reading, with a two-week blind spot in between. Harder. This is the one we are graded on.

And two ways to check a model:

Offline (your laptop)Online (leaderboard)
What it isHide the last chunk of your own data, predict it, check against the chunk you hidUpload predictions; the website scores them against answers only staff have
Which gapgap 336 — matches the graded testgap 0 only — easier, feedback only
Do we need it?Yes — this is what mattersNo — nice-to-have, and locked for us right now
The takeaway

The gap-336 test you run offline is the real practice exam. The leaderboard is a different, easier one that is only feedback (and locked for us right now). Choose your models on the offline gap-336 numbers, not the leaderboard.

Three scores, and why they won't match

By the end you'll see your model scored in three different places, giving three different numbers. That is completely normal — here is what each one is, why they differ, and which one is your grade. No panic required.

First, the absolute basics: a model does two separate jobs

Why read this

This trips up everyone at the start, and it explains why the CSV we uploaded was the baseline and not our own model. A machine-learning model is used in two completely different ways, at different times.

Training (fitting)Prediction (inference)
What it doeslearns from data we already know the answers to — it adjusts its internal numbers to get bettertakes the already-trained model and produces answers for new data it has never seen
What comes outa saved model file (checkpoint.pt) — no submittable predictionsa predictions CSV — the thing you upload
In our projectpython -m src.train ... — done many times (that's the whole model ladder)predict.py — not written yet (Phase 9)

So — everything we've done so far has been training. Training makes the model better and saves it, but it never produces a predictions file you can hand in. To get predictions you run the trained model in prediction mode on new data — and that is exactly what predict.py will do.

That is why the CSV we uploaded to the leaderboard was the baseline, not our model: the baseline (seasonal_mean) can be computed directly, with no trained model, but our trained model has no way to produce a CSV until predict.py exists. We've trained a strong model — we just haven't run it to make predictions yet.

The lifecycle, in one line

Train once (save the checkpoint) → predict many times (make CSVs with predict.py) → upload the CSV as often as you like for leaderboard feedback → zip predict.py + the checkpoint once as the final graded submission.

What is a baseline, and how is ours computed?

Why

A "baseline" is not a trained model — it's a dead-simple rule computed straight from the data, with no learning at all. It exists to set a floor: any real model has to beat it, or the model isn't doing anything.

We have four, from dumbest to smartest (rough leaderboard WAPE in brackets):

BaselineThe rule~WAPE
naive_last_valuerepeat each series' last observed value for all 336 hours~48%
lag24_repeatrepeat the last 24 hours, tiled forward~47%
lag168_repeatrepeat the last week (168 h), tiled forward~47%
seasonal_meanfor each series, the average at each (day-of-week, hour); to predict a future hour, look up that slot's historical average~34% — best

None of these learns anything — they're formulas in src/baselines.py. Running write_baselines(...) just computes the seasonal averages from train.csv and writes the CSV. That is the whole "model." seasonal_mean is the strongest because it knows a Tuesday 9 am tends to look like other Tuesday 9 ams.

So how is that different from our model?

Baseline (e.g. seasonal_mean)Our model (LSTM + covariates)
Does it learn?No — a fixed formula, same every runYes — weights trained by gradient descent
Uses covariates?NoYes — that's where most of the win comes from
Rough WAPE~34%~17% — about half the error

That ~34% → ~17% jump is the point of building a model: a learned network with covariates roughly halves the error of the best dumb rule.

Reading the leaderboard

It lists several baseline reference rows at different scores (naive ~48%, seasonal ~34%). "Beating the baseline" means getting below the best one (seasonal, ~34%). Entries below ~34% are real trained models; entries sitting at ~34–48% are groups who uploaded a baseline (or a model that isn't working yet). Our seasonal_mean upload landed at ~34% because it is that baseline — our real model (~17%) will sit far below it once predict.py runs it.

Why they won't be the same number

  • Different data. Local uses pieces of your own training data; the leaderboard uses a hidden validation slice; the grade uses a hidden test slice. Different data → different difficulty.
  • Different gap. Local and the grade are gap 336 (predict a 2-week window that starts 2 weeks after your last data). The public leaderboard is gap 0 (predict the 2 weeks immediately after) — an easier task, so that number is not comparable to your grade.
  • Different randomness. Seeds, the exact window, rounding — a little wobble on top.

Expect the private grade to be a bit worse than your local number

Your local ~0.17 is measured on folds you looked at while choosing your model, so it's slightly optimistic. The private test is fresh data you never touched, so the model has to generalise — and it almost always loses a little there. A model that's 0.17 at home might be, say, 0.19–0.22 on the private test. That's not a bug or a mistake; it's the normal "reality tax," and every honest team plans for it. In the report, say it plainly: "local WAPE X; we expect the held-out test to be modestly higher."

"You running it" vs "them running it"

Locally, you run training and evaluation on data you have. For the grade, the instructors run your predict.py on data you have never seen — on their machine, no internet, no train.csv. So your submission must be totally self-contained: the checkpoint carries the weights, the scaler, the series order, and the last window of history. Anything that secretly depends on your laptop or on train.csv produces garbage there — the single most common way student submissions fail.

Which score is the "real" one?

The private grade (gap 336) is the only one that counts, and it's the one you see last and should expect to be the least flattering of the three. So treat your local gap-336 number as an optimistic estimate, assume the grade will be a touch higher (worse), and treat the public gap-0 leaderboard as a loose sanity check on a different, easier task. Report all three honestly and you're doing science, not cherry-picking.

Your specific question: should diagnose.ipynb also be a .py?

Yes, and it is a ten-minute job. Three reasons, in order of how much they will bite you:

  1. Those numbers go in your report. Section 4.1 needs series count, history length, missing-value rates, target statistics. You want to regenerate them with one command after any change, not hunt through cell outputs.

"""Evaluation metrics. WAPE is the primary; everything else mirrors the leaderboard."""
import numpy as np


def _prep(y, p):
    y = np.asarray(y, dtype=np.float64).ravel()
    p = np.asarray(p, dtype=np.float64).ravel()
    assert y.shape == p.shape, f"shape mismatch {y.shape} vs {p.shape}"
    assert np.isfinite(p).all(), "predictions contain NaN or inf"
    return y, p


def mae(y, p):
    y, p = _prep(y, p)
    return float(np.abs(y - p).mean())


def mse(y, p):
    y, p = _prep(y, p)
    return float(((y - p) ** 2).mean())


def rmse(y, p):
    return float(np.sqrt(mse(y, p)))


def wape(y, p):
    """Sum of absolute errors over sum of truth. Equals MAE up to a constant."""
    y, p = _prep(y, p)
    return float(np.abs(y - p).sum() / np.abs(y).sum())


def mape(y, p, eps=1e-8):
    y, p = _prep(y, p)
    return float((np.abs(y - p) / np.maximum(np.abs(y), eps)).mean())


def smape(y, p, eps=1e-8):
    y, p = _prep(y, p)
    denom = np.maximum((np.abs(y) + np.abs(p)) / 2.0, eps)
    return float((np.abs(y - p) / denom).mean())


def all_metrics(y, p):
    return {"wape": wape(y, p), "mae": mae(y, p), "rmse": rmse(y, p),
            "mse": mse(y, p), "mape": mape(y, p), "smape": smape(y, p)}

Global standardisation and RevIN. The state() / from_state() pair is what survives into the checkpoint.

"""Two-level normalisation: a global per-feature scaler, plus per-window RevIN."""
import numpy as np
import torch
import torch.nn as nn


class GlobalScaler:
    """Per-feature standardisation. MUST be fitted on training hours only."""

    def __init__(self, mean=None, std=None):
        self.mean, self.std = mean, std

    def fit(self, X, upto):
        """X: (S, T, F) float32.  upto: exclusive hour index of the training cut."""
        flat = X[:, :upto, :].reshape(-1, X.shape[2])
        self.mean = flat.mean(0)
        self.std = flat.std(0) + 1e-6
        return self

    def transform(self, X):
        return ((X - self.mean) / self.std).astype("float32")

    def state(self):
        # plain lists so torch.load(weights_only=True) never chokes on them
        return {"mean": [float(v) for v in self.mean],
                "std": [float(v) for v in self.std]}

    @staticmethod
    def from_state(d):
        return GlobalScaler(np.asarray(d["mean"], "float32"),
                            np.asarray(d["std"], "float32"))


class RevIN(nn.Module):
    """Reversible instance normalisation (Kim et al., ICLR 2022).

    Normalise each window by its own statistics, predict a shape, then put the
    scale back. Absorbs both between-series scale differences and within-series
    level shifts. Ten lines; usually the single largest improvement in the model.
    """

    def __init__(self, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.mu = None
        self.sd = None

    def norm(self, x):
        """x: (B, L) target history. Stores stats for the matching denorm()."""
        self.mu = x.mean(dim=1, keepdim=True)          # (B, 1)
        self.sd = x.std(dim=1, keepdim=True) + self.eps
        return (x - self.mu) / self.sd

    def denorm(self, y):
        """y: (B, H) prediction in normalised space."""
        assert self.mu is not None, "call norm() before denorm()"
        return y * self.sd + self.mu

"""Loading, windowing and inference-time assembly.

Layout convention used everywhere:
    X : (S, T, F) float32   dynamic features, already scaled
    Y : (S, T)    float32   target
    S = 96 series, T = 4320 train hours, F = number of feature columns
"""
import numpy as np
import pandas as pd
import torch
from torch.utils.data import Dataset, DataLoader

H = 336                 # forecast horizon, fixed by the task
N_TRAIN_HOURS = 4320    # hours per series in train.csv
STATIC = ["nominal_capacity", "zone_sin", "zone_cos"]
CALENDAR = ["hour_sin", "hour_cos", "dow_sin", "dow_cos", "is_weekend", "trend"]


# --------------------------------------------------------------------------
# splitting

def fold_bounds(fold, total=N_TRAIN_HOURS, h=H):
    """Rolling origin. Fold 0 scores the last h hours, fold 1 the h before that.

    Returns (train_end, score_start, score_end) as hour indices.
    train_end == score_start: training may never touch the scored region.
    """
    score_end = total - fold * h
    score_start = score_end - h
    assert score_start > 0, f"fold {fold} runs off the start of the data"
    return score_start, score_start, score_end

def load_cube(path, use_trend=True, fill="ffill", add_mask=False):
    """Long CSV -> (X, Y, series, hours, feats, static).

    X and Y are UNSCALED here; fit the scaler afterwards so it only sees
    training hours.
    """
    df = pd.read_csv(path, parse_dates=["timestamp"])
    df = df.sort_values(["series_id", "timestamp"]).reset_index(drop=True)

    series = sorted(df.series_id.unique())        # FIXED order, save it
    hours = np.sort(df.timestamp.unique())
    S, T = len(series), len(hours)
    assert len(df) == S * T, "frame is not rectangular; check for gaps first"

    drop = ("series_id", "timestamp", "target") + tuple(STATIC)
    feats = [c for c in df.columns if c not in drop]
    if not use_trend:
        feats = [c for c in feats if c != "trend"]

    gappy = [c for c in feats if df[c].isna().any()]
    if add_mask:
        for c in gappy:
            df[c + "_isna"] = df[c].isna().astype("float32")
        feats = feats + [c + "_isna" for c in gappy]

    df = _fill_na(df, gappy, fill)

    X = df[feats].to_numpy("float32").reshape(S, T, len(feats))
    Y = df["target"].to_numpy("float32").reshape(S, T)
    St = (df.groupby("series_id")[STATIC].first()
            .loc[series].to_numpy("float32"))

    # the reshape is only correct if the sort worked; prove it
    first = df[df.series_id == series[0]].sort_values("timestamp")
    assert np.allclose(Y[0], first.target.to_numpy("float32")), "cube scrambled"
    assert np.isfinite(X).all() and np.isfinite(Y).all()
    return X, Y, series, hours, feats, St


def _fill_na(df, cols, how):
    if not cols:
        return df
    if how == "ffill":
        df[cols] = df.groupby("series_id")[cols].ffill()
        df[cols] = df.groupby("series_id")[cols].bfill()
    elif how == "mean":
        df[cols] = df[cols].fillna(df[cols].mean())
    elif how == "zero":
        pass
    else:
        raise ValueError(f"unknown fill strategy {how!r}")
    df[cols] = df[cols].fillna(0.0)
    return df


# --------------------------------------------------------------------------
# windowing
# --------------------------------------------------------------------------
class WindowDataset(Dataset):
    """Every legal (series, start-hour) pair strictly inside [0, train_end)."""

    def __init__(self, X, Y, L, H_=H, train_end=N_TRAIN_HOURS, gap=0):
        self.X, self.Y, self.L, self.H, self.gap = X, Y, L, H_, gap
        self.train_end = train_end
        n_starts = train_end - L - gap - H_ + 1
        assert n_starts > 0, (
            f"lookback {L} + gap {gap} + horizon {H_} exceeds "
            f"{train_end} available hours")
        S = X.shape[0]
        self.index = [(s, t) for s in range(S) for t in range(n_starts)]

    def __len__(self):
        return len(self.index)

    def __getitem__(self, i):
        s, t = self.index[i]
        L, H_, g = self.L, self.H, self.gap
        assert t + L + g + H_ <= self.train_end, "window reaches into scored region"
        f0 = t + L + g                                  # forecast origin
        x_hist = self.X[s, t:t + L]                     # (L, F)
        y_hist = self.Y[s, t:t + L, None]               # (L, 1)
        x_fut = self.X[s, f0:f0 + H_]                   # (H, F)
        y_fut = self.Y[s, f0:f0 + H_]                   # (H,)
        return (torch.from_numpy(np.concatenate([x_hist, y_hist], 1)),
                torch.from_numpy(x_fut),
                torch.from_numpy(y_fut),
                s)


def make_loader(ds, bs=64, shuffle=True):
    # num_workers=0: slicing is already just NumPy indexing, and multiprocessing
    # data loading is unreliable on macOS.
    return DataLoader(ds, batch_size=bs, shuffle=shuffle,
                      num_workers=0, drop_last=shuffle)


def validation_batch(Xs, Y, series, L, train_end, s0, s1, gap=0):
    """One window per series, mirroring the real task exactly.

    gap=0   : history ends at train_end, forecast is [s0, s1)  -- validation.
    gap=336 : history must stop `gap` hours EARLIER so that the distance from
              the last observed hour to the forecast origin matches what the
              model saw in training. Otherwise you score a gap-336 model under
              gap-0 conditions and the number is meaningless.
    """
    hist_end = train_end - gap
    assert hist_end - L >= 0, f"L={L} + gap={gap} exceeds {train_end} hours"
    xh = np.stack([
        np.concatenate([Xs[s, hist_end - L:hist_end],
                        Y[s, hist_end - L:hist_end, None]], 1)
        for s in range(len(series))]).astype("float32")
    xf = Xs[:, s0:s1].astype("float32")
    return (torch.from_numpy(xh), torch.from_numpy(xf), Y[:, s0:s1])

def _calendar_from_timestamps(ts):
    """Rebuild the deterministic calendar columns for arbitrary future hours."""
    ts = pd.to_datetime(pd.Series(ts))
    h, d = ts.dt.hour.to_numpy(), ts.dt.dayofweek.to_numpy()
    return {
        "hour_sin": np.sin(2 * np.pi * h / 24), "hour_cos": np.cos(2 * np.pi * h / 24),
        "dow_sin": np.sin(2 * np.pi * d / 7),   "dow_cos": np.cos(2 * np.pi * d / 7),
        "is_weekend": (d >= 5).astype("float64"),
    }


def _append_future(Xf, g, hist, horizon_hours, features, scaler, H_):
    """Covariates for the hours being predicted, real if given else synthesised."""
    fut = g[g.timestamp.isin(horizon_hours)].sort_values("timestamp")
    if len(fut) != H_:
        fut = pd.DataFrame({"timestamp": horizon_hours})
        for c in features:
            fut[c] = hist[c].iloc[-1] if len(hist) else 0.0
        for c, v in _calendar_from_timestamps(horizon_hours).items():
            if c in features:
                fut[c] = v
    Xf.append(scaler.transform(fut[features].to_numpy("float32")[None])[0])


def prepare_inference_cube(input_csv, forecast_index, features, series_order,
                           scaler, L, H_=H, extra_history_csv=None,
                           fallback_x=None, fallback_y=None,
                           fallback_end=None, verbose=True):
    """Build (Xh, Xf) for prediction. Handles both covariate regimes.

    Xh : (S, L, F+1) scaled history window ending immediately before the horizon
    Xf : (S, H, F)   scaled covariates for the hours being predicted

    Auto-detects whether real future covariates are supplied. If they are not,
    the calendar columns are synthesised from the timestamps and the remaining
    features are held at their last observed value.

    fallback_x / fallback_y are the last L hours baked into the checkpoint at
    training time, shaped (S, L, F) and (S, L). They are used for any series
    whose input file carries no usable target history -- which is exactly what
    happens if test_input.csv mirrors validation_input.csv (covariates only).
    Without them the model would run on fabricated history and score like noise.
    """
    df = pd.read_csv(input_csv, parse_dates=["timestamp"])
    if extra_history_csv is not None:
        hist_extra = pd.read_csv(extra_history_csv, parse_dates=["timestamp"])
        df = pd.concat([hist_extra, df], ignore_index=True)
    df = (df.drop_duplicates(["series_id", "timestamp"], keep="last")
            .sort_values(["series_id", "timestamp"]).reset_index(drop=True))

    fi = forecast_index.copy()
    fi["timestamp"] = pd.to_datetime(fi["timestamp"])
    horizon_hours = np.sort(fi.timestamp.unique())[-H_:]
    assert len(horizon_hours) == H_, f"index has {len(horizon_hours)} hours, need {H_}"

    # which rows are history (target known) vs horizon
    if "target" not in df.columns:
        df["target"] = np.nan
    is_horizon = df.timestamp.isin(horizon_hours)

    have_future = bool(is_horizon.sum()) and \
        df.loc[is_horizon, [c for c in features if c in df.columns]].notna().any().any()
    if verbose:
        print("future covariates:", "supplied" if have_future else "synthesised")

    # How far is the forecast origin from the last hour we actually observed?
    # Must match the --gap the model was TRAINED with, or the numbers are void.
    obs = df.loc[df.target.notna(), "timestamp"]
    last_obs = obs.max() if len(obs) else (
        pd.Timestamp(fallback_end) if fallback_end else None)
    if last_obs is not None:
        gap = int((horizon_hours[0] - np.datetime64(last_obs))
                  / np.timedelta64(1, "h")) - 1
        if verbose:
            print(f"last observed target: {last_obs}")
            print(f"forecast origin gap : {gap} h")
        if gap > 0:
            print(f"WARNING: {gap}h gap between history and horizon. "
                  f"Use a checkpoint trained with --gap {gap}.")

    # make sure every feature column exists, then fill
    for c in features:
        if c not in df.columns:
            df[c] = np.nan
    cal = _calendar_from_timestamps(df.timestamp)
    for c, v in cal.items():
        if c in features:
            df[c] = df[c].fillna(pd.Series(v, index=df.index))
    gappy = [c for c in features if df[c].isna().any()]
    df = _fill_na(df, gappy, "ffill")

    Xh, Xf = [], []
    for sid in series_order:
        g = df[df.series_id == sid].sort_values("timestamp")
        hist = g[~g.timestamp.isin(horizon_hours)]
        usable = hist[hist.target.notna()]

        if len(usable) < L:
            # The input file cannot supply a full context window. Use the
            # history baked into the checkpoint rather than inventing one.
            if fallback_x is None:
                raise RuntimeError(
                    f"{sid}: only {len(usable)} usable history rows, need {L}, "
                    f"and the checkpoint carries no baked history. Retrain with "
                    f"history_x/history_y saved, or lower --lookback.")
            k = series_order.index(sid)
            if verbose and sid == series_order[0]:
                print(f"history: using checkpoint-baked window "
                      f"({len(usable)} usable rows in input, need {L})")
            Xh.append(np.concatenate(
                [np.asarray(fallback_x[k], "float32"),
                 np.asarray(fallback_y[k], "float32")[:, None]], 1))
            _append_future(Xf, g, hist, horizon_hours, features, scaler, H_)
            continue

        hist = usable.iloc[-L:]

        _append_future(Xf, g, hist, horizon_hours, features, scaler, H_)

        xh_f = scaler.transform(hist[features].to_numpy("float32")[None])[0]
        y_h = hist["target"].fillna(method="ffill").fillna(0.0) \
                  .to_numpy("float32")[:, None]
        Xh.append(np.concatenate([xh_f, y_h], 1))

    return (np.stack(Xh).astype("float32"),
            np.stack(Xf).astype("float32"),
            list(series_order), horizon_hours)

src/models.py

All five architectures behind one signature, plus build_model and build_model_from_config.

"""Every model in the ladder, plus the dispatchers train.py and predict.py need.

Shared contract — all models implement:
    forward(x_hist, x_fut, sidx) -> (B, H)
      x_hist : (B, L, F+1)  scaled features with the target as the LAST channel
      x_fut  : (B, H, F)    scaled known-future covariates (may be ignored)
      sidx   : (B,)         long tensor of series indices
"""
import torch
import torch.nn as nn

from .scaling import RevIN


# --------------------------------------------------------------------------
# shared pieces
# --------------------------------------------------------------------------
class CovariateHead(nn.Module):
    """Squeeze (B, H, F) known-future covariates into an additive (B, H).

    Zero-initialised output layer, so the model starts identical to the version
    without covariates and only learns to use them where they help. That is what
    makes the with/without ablation a fair comparison.
    """

    def __init__(self, n_feat, H, d=64, dropout=0.1):
        super().__init__()
        self.point = nn.Sequential(
            nn.Linear(n_feat, d), nn.GELU(), nn.Dropout(dropout), nn.Linear(d, 1))
        self.mix = nn.Linear(H, H)
        nn.init.zeros_(self.mix.weight)
        nn.init.zeros_(self.mix.bias)

    def forward(self, x_fut):
        return self.mix(self.point(x_fut).squeeze(-1))       # (B, H)


class SeriesConditioner(nn.Module):
    """Series identity, three ways.

    none   : returns None. RevIN already removes most per-unit scale differences.
    embed  : nn.Embedding(S, d). Most expressive, breaks on unseen series.
    static : projects nominal_capacity / zone_sin / zone_cos. Generalises.
    """

    def __init__(self, mode, n_series, d_out, static_table=None):
        super().__init__()
        self.mode = mode
        if mode == "embed":
            self.emb = nn.Embedding(n_series, d_out)
            nn.init.normal_(self.emb.weight, std=0.02)
        elif mode == "static":
            assert static_table is not None, "static mode needs the static table"
            self.register_buffer("table", torch.as_tensor(static_table).float())
            self.proj = nn.Sequential(
                nn.Linear(self.table.shape[1], d_out), nn.GELU(),
                nn.Linear(d_out, d_out))
        elif mode != "none":
            raise ValueError(f"unknown series_id mode {mode!r}")

    def forward(self, sidx):
        if self.mode == "none":
            return None
        if self.mode == "embed":
            return self.emb(sidx)                            # (B, d)
        return self.proj(self.table[sidx])                   # (B, d)


def _target(x_hist):
    return x_hist[..., -1]                                   # (B, L)


# --------------------------------------------------------------------------
# rung 2 — linear (DLinear-style)
# --------------------------------------------------------------------------
class LinearForecaster(nn.Module):
    def __init__(self, L, H, n_feat, use_revin=True, covariates=False,
                 series_id="none", n_series=96, static_table=None, **_):
        super().__init__()
        self.proj = nn.Linear(L, H)
        self.revin = RevIN() if use_revin else None
        self.cov = CovariateHead(n_feat, H) if covariates else None
        self.cond = SeriesConditioner(series_id, n_series, H, static_table)
        if series_id != "none":
            self.cond_scale = nn.Parameter(torch.zeros(1))

    def forward(self, x_hist, x_fut=None, sidx=None):
        y = _target(x_hist)
        if self.revin:
            y = self.revin.norm(y)
        out = self.proj(y)
        if self.revin:
            out = self.revin.denorm(out)
        if self.cov is not None and x_fut is not None:
            out = out + self.cov(x_fut)
        c = self.cond(sidx) if sidx is not None else None
        if c is not None:
            out = out + self.cond_scale * c
        return out

# rung 3 — MLP
# --------------------------------------------------------------------------
class MLPForecaster(nn.Module):
    def __init__(self, L, H, n_feat, d_model=512, dropout=0.2, use_revin=True,
                 covariates=False, series_id="none", n_series=96,
                 static_table=None, **_):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(L, d_model), nn.GELU(), nn.Dropout(dropout),
            nn.Linear(d_model, d_model), nn.GELU(), nn.Dropout(dropout),
            nn.Linear(d_model, H))
        self.revin = RevIN() if use_revin else None
        self.cov = CovariateHead(n_feat, H) if covariates else None
        self.cond = SeriesConditioner(series_id, n_series, H, static_table)
        if series_id != "none":
            self.cond_scale = nn.Parameter(torch.zeros(1))

    def forward(self, x_hist, x_fut=None, sidx=None):
        y = _target(x_hist)
        if self.revin:
            y = self.revin.norm(y)
        out = self.net(y)
        if self.revin:
            out = self.revin.denorm(out)
        if self.cov is not None and x_fut is not None:

# --------------------------------------------------------------------------
# rung 4 — LSTM
# --------------------------------------------------------------------------
class LSTMForecaster(nn.Module):
    def __init__(self, L, H, n_feat, d_model=128, layers=2, dropout=0.2,
                 use_revin=True, covariates=False, series_id="none",
                 n_series=96, static_table=None, **_):
        super().__init__()
        self.lstm = nn.LSTM(n_feat + 1, d_model, num_layers=layers,
                            batch_first=True,
                            dropout=dropout if layers > 1 else 0.0)
        self.head = nn.Linear(d_model, H)
        self.revin = RevIN() if use_revin else None
        self.cov = CovariateHead(n_feat, H) if covariates else None
        self.cond = SeriesConditioner(series_id, n_series, H, static_table)
        if series_id != "none":
            self.cond_scale = nn.Parameter(torch.zeros(1))

    def forward(self, x_hist, x_fut=None, sidx=None):
        x = x_hist
        if self.revin:
            y = self.revin.norm(_target(x_hist))
            x = torch.cat([x[..., :-1], y.unsqueeze(-1)], -1)
        h, _ = self.lstm(x)                                  # (B, L, d)
        out = self.head(h[:, -1])                            # (B, H)
        if self.revin:
            out = self.revin.denorm(out)
        if self.cov is not None and x_fut is not None:
            out = out + self.cov(x_fut)
        c = self.cond(sidx) if sidx is not None else None
        if c is not None:
            out = out + self.cond_scale * c
        return out


# --------------------------------------------------------------------------
# rung 5 — PatchTST (Nie et al., ICLR 2023)
# --------------------------------------------------------------------------
class PatchTST(nn.Module):
    def __init__(self, L, H, n_feat, patch_len=16, stride=8, d_model=128,
                 layers=3, n_heads=8, d_ff=256, dropout=0.2, use_revin=True,
                 channel_mixing=False, target_only=False, covariates=False,
                 series_id="none", n_series=96, static_table=None, **_):
        super().__init__()
        assert L > patch_len, f"lookback {L} must exceed patch_len {patch_len}"
        self.pl, self.st = patch_len, stride
        self.n_patch = (L - patch_len) // stride + 1
        self.C = 1 if target_only else n_feat + 1
        self.mixing, self.target_only = channel_mixing, target_only

        self.embed = nn.Linear(patch_len, d_model)
        self.pos = nn.Parameter(torch.randn(1, self.n_patch, d_model) * 0.02)
        self.drop = nn.Dropout(dropout)

        enc = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=n_heads, dim_feedforward=d_ff,
            dropout=dropout, activation="gelu",
            batch_first=True,      # without this your tensors are silently transposed
            norm_first=True)       # pre-norm; post-norm needs warmup to stay stable
        self.backbone = nn.TransformerEncoder(enc, num_layers=layers)

        head_in = self.n_patch * d_model * (self.C if channel_mixing else 1)
        self.head = nn.Linear(head_in, H)

        self.revin = RevIN() if use_revin else None
        self.cov = CovariateHead(n_feat, H) if covariates else None
        self.cond = SeriesConditioner(series_id, n_series, d_model, static_table)
        self.use_cond = series_id != "none"

    def _patchify(self, z):
        """z: (N, L) -> (N, n_patch, patch_len)"""
        return z.unfold(dimension=1, size=self.pl, step=self.st)

    def forward(self, x_hist, x_fut=None, sidx=None):
        B, L, _ = x_hist.shape
        x = x_hist[..., -1:] if self.target_only else x_hist
        if self.revin:
            tgt = self.revin.norm(_target(x_hist))           # (B, L)
            x = torch.cat([x[..., :-1], tgt.unsqueeze(-1)], -1)

        # channel independence: fold channels into the batch dimension
        z = x.permute(0, 2, 1).reshape(B * self.C, L)        # (B*C, L)
        p = self.embed(self._patchify(z)) + self.pos         # (B*C, P, d)

        if self.use_cond and sidx is not None:
            c = self.cond(sidx)                              # (B, d)
            p = p + c.repeat_interleave(self.C, 0).unsqueeze(1)

        h = self.backbone(self.drop(p))                      # (B*C, P, d)

        if self.mixing:
            out = self.head(h.reshape(B, -1))                # (B, H)
        else:
            out = self.head(h.reshape(B * self.C, -1))       # (B*C, H)
            out = out.reshape(B, self.C, -1)[:, -1]          # target channel

        if self.revin:
            out = self.revin.denorm(out)
        if self.cov is not None and x_fut is not None:
            out = out + self.cov(x_fut)
        return out

def main(argv=None):
    a = get_args(argv)
    torch.manual_seed(a.seed)
    np.random.seed(a.seed)
    dev = pick_device(a.device)
    t0 = time.time()
    L = a.lookback

    # ---- data ------------------------------------------------------------
    X, Y, series, hours, feats, St = load_cube(
        a.data, use_trend=bool(a.use_trend), fill=a.fill, add_mask=bool(a.add_mask))
    train_end, s0, s1 = fold_bounds(a.fold)

    scaler = GlobalScaler().fit(X, upto=train_end)
    Xs = scaler.transform(X)

    dl = make_loader(WindowDataset(Xs, Y, L=L, H_=H, train_end=train_end,
                                   gap=a.gap),
                     bs=a.batch_size, shuffle=True)
    vx, vxf, vy = validation_batch(Xs, Y, series, L, train_end, s0, s1,
                                   gap=a.gap)
    vx, vxf = vx.to(dev), vxf.to(dev)
    vsi = torch.arange(len(series), device=dev)

    # ---- model -----------------------------------------------------------
    model = build_model(a, n_feat=Xs.shape[2], n_series=len(series),
                        L=L, H=H, static_table=St).to(dev)
    n_par = sum(p.numel() for p in model.parameters())
    print(f"{a.model}: {n_par:,} params on {dev} | "
          f"{len(dl.dataset):,} windows | fold {a.fold}")

    crit = LOSSES[a.loss]()
    opt = torch.optim.AdamW(model.parameters(), lr=a.lr, weight_decay=a.weight_decay)
    sched = torch.optim.lr_scheduler.OneCycleLR(
        opt, max_lr=a.lr, total_steps=max(a.epochs * len(dl), 1))

    best, bad, best_state, best_metrics = 1e9, 0, None, None
    for ep in range(a.epochs):
        model.train()
        tot = n = 0
        for xh, xf, yf, si in dl:
            xh, xf, yf, si = xh.to(dev), xf.to(dev), yf.to(dev), si.to(dev)
            opt.zero_grad()
            loss = crit(model(xh, xf, si), yf)
            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            opt.step()
            sched.step()
            tot += loss.item() * len(yf)
            n += len(yf)

        model.eval()
        with torch.no_grad():
            pv = model(vx, vxf, vsi).cpu().numpy()
        m = all_metrics(vy, pv)
        print(f"  ep{ep:02d}  train {tot / n:.4f}   val WAPE {m['wape']:.4f}")

        if m["wape"] < best - 1e-4:
            best, bad, best_metrics = m["wape"], 0, m
            best_state = {k: v.detach().cpu().clone()
                          for k, v in model.state_dict().items()}
        else:
            bad += 1
            if bad >= a.patience:
                print("  early stop")
                break

    # ---- save everything inference will need -----------------------------
    import pathlib
    pathlib.Path(a.out).mkdir(parents=True, exist_ok=True)
    run_id = (f"{a.model}_f{a.fold}_s{a.seed}_L{L}_{a.loss}"
              f"{'_revin' if a.revin else ''}{'_cov' if a.covariates else ''}"
              f"{'' if a.series_id == 'none' else '_' + a.series_id}")
    torch.save({
        "state_dict": best_state,
        "config": vars(a),
        "scaler": scaler.state(),
        "series": list(series),
        # last L hours of every channel, per series -- the model's only
        # history at inference if test_input.csv ships none. ~6 MB at L=720.
        "history_x": Xs[:, train_end - L:train_end].astype("float32"),
        "history_y": Y[:, train_end - L:train_end].astype("float32"),
        "history_end": str(hours[train_end - 1]),
        "features": list(feats),
        "static_table": St.tolist(),
        "L": L, "H": H,
    }, f"{a.out}/{run_id}.pt")

    log_run(run_id=run_id, params=n_par,
            minutes=round((time.time() - t0) / 60, 1),
            **{k: v for k, v in vars(a).items() if k in
               ("model", "fold", "seed", "lookback", "loss", "revin", "covariates",
                "series_id", "use_trend", "fill", "add_mask", "patch_len", "stride",
                "d_model", "layers", "dropout", "lr", "epochs", "batch_size", "notes")},
            **best_metrics)
    print(f"best WAPE {best:.4f}  ->  {a.out}/{run_id}.pt")


if __name__ == "__main__":
    main()

        fallback_x=ck.get("history_x"), fallback_y=ck.get("history_y"),
        fallback_end=ck.get("history_end"))

    missing = set(fi.series_id.unique()) - set(series)
    assert not missing, f"index has series absent from the checkpoint: {sorted(missing)}"

    model = build_model_from_config(

    fi["_ts"] = pd.to_datetime(fi["timestamp"])

\begin{abstract}
We forecast 96 operational load series 336 hours ahead from 22 known-future
covariates, scored by WAPE. Four architectures --- a linear projector, an MLP,
an LSTM and a channel-independent PatchTST --- each model uses reversible instance normalization and the 
same additive covariate head, and all are trained with the same setup. On a rolling-origin protocol with 
a 336-hour gap the LSTM with covariates is best (WAPE 0.169), ahead of PatchTST (0.188) and the
linear model (0.195), roughly half the strongest baseline (seasonal mean, 0.326).
The ablation study shows that the covariate head is the main source of improvement,
whose removal exceeds the seed-noise floor: it roughly halves the
error, while normalization, detrending, imputation, lookback and loss are all
within noise. The same architecture transfers to the ETT benchmark without
retuning, indicating the gain comes from the covariates rather than
dataset-specific tuning.
\end{abstract}

\section{Introduction}
Operational load forecasting drives staffing, capacity and maintenance planning,
where errors two weeks out are costly. We study a benchmark of 96 hourly load
series (\texttt{unit\_000}--\texttt{unit\_095}) covering 4320 hours from
2023-01-01 to 2023-06-29. For every series the task is to predict the next
$H=336$ hours, evaluated by the weighted absolute percentage error
\begin{equation}
\mathrm{WAPE} = \frac{\sum_t \lvert y_t - \hat y_t\rvert}{\sum_t \lvert y_t\rvert}.
\end{equation}
Two properties make the task hard: the horizon is long --- two weeks of hourly
steps, so error accumulates --- and each series ships 22 \emph{known-future}
covariates (calendar signals, demand and staffing forecasts, risk indicators)
that a good model should exploit. Our contributions are (i) a controlled
comparison of four forecasting architectures under a single training and
evaluation harness; (ii) a single-factor ablation that isolates the covariate
head as the dominant driver of accuracy, measured against a seed-noise floor;
and (iii) a cross-dataset transfer test on ETT confirming that the results hold 
beyond the original dataset.

\section{Related Work}
\textbf{Classical and recurrent models.} Seasonal-naive and moving-average
baselines remain strong on periodic load data and anchor our evaluation.
Recurrent networks, notably the LSTM \citep{hochreiter1997lstm}, were the default
neural forecaster before attention and remain a competitive baseline.
\textbf{Transformer forecasters.} A line of work adapts self-attention to long
sequences --- Informer \citep{zhou2021informer} and the channel-independent,
patch-based PatchTST \citep{nie2023patchtst}, which reports that longer lookbacks
and patching help long-horizon accuracy. \textbf{The linear critique.}
\citet{zeng2023dlinear} show simple linear forecasters match or beat many
transformers on standard benchmarks, making a linear model the more demanding
baseline; we include it deliberately. \textbf{Normalization.} Reversible instance
normalization \citep{kim2022revin} counters the distribution shift between history
and horizon and is applied to every model in our comparison.

\textbf{Problem.} For each series we take a lookback of $L$ target values and the
$F=22$ covariates over the window and the horizon, and predict the $H=336$ future
targets directly (one shot, not autoregressively). \textbf{Data pipeline.} The
long CSV is reshaped into a cube of shape $(S{=}96, T{=}4320, F{=}22)$. Missing
values, present in ten covariate columns, are filled forward then backward
\emph{within} each series so nothing crosses the train/score boundary. Calendar
features (hour and day-of-week as sine/cosine, a weekend flag, a linear trend) and
three static per-series features (nominal capacity, zone as sine/cosine) accompany
the dynamic covariates; the target's strong diurnal structure is shown in
Figure~\ref{fig:data}. \textbf{Normalization.} Two levels: a global per-feature
standardization fitted only on training hours, and per-window RevIN
\citep{kim2022revin} on the target channel. \textbf{Architectures.} All models
share one interface (Figure~\ref{fig:arch}). The \emph{linear} model projects the $L$ history targets to
$H$ outputs; the \emph{MLP} adds two GELU layers; the \emph{LSTM}
\citep{hochreiter1997lstm} reads the window step by step; and \emph{PatchTST}
\citep{nie2023patchtst} patchifies the window, embeds each patch and applies a
transformer encoder channel-independently. \textbf{Covariate head.} Each model
optionally adds a zero-initialized linear map from the $H\times F$ future
covariates to an additive correction on the forecast; being additive and
zero-initialized it is a pure augmentation, reducing exactly to the target-only
model when off. \textbf{Training.} We minimize the Huber loss (robust, aligned
with WAPE's absolute-error character) using Adam and a one-cycle schedule, keeping
the best-validation checkpoint. \textbf{Validation.} A rolling-origin protocol of
three folds with a 336-hour gap between each training window and the region it is
scored on, so no training target reaches into a scored horizon; this matches the
graded private-test geometry. The model comparison reports the mean over three
folds; seed variability, estimated by repeating the final configuration across
seeds 0--2, gives a noise floor of $0.045$ WAPE ($2\sigma$) that we use to judge
which ablations are conclusive.

Opening — concrete beats grand

Operational load forecasting supports staffing and capacity decisions that must be made days in advance. We study a dataset of 96 anonymised operations units observed hourly over 180 days, each described by 22 covariates, where the task is to predict a scalar load index 336 hours (14 days) into the future. Performance is measured by Weighted Absolute Percentage Error.

Why it is hard — three specific difficulties, not generic ones

Three properties make this difficult. First, the horizon is long relative to the dominant seasonality: at 336 steps the most recent observation is two weeks stale, so predictive signal must come from periodic structure and exogenous covariates rather than persistence. Second, ten of the 22 covariates contain approximately 4.5% missing values, requiring an imputation strategy whose effect on downstream accuracy is not obvious a priori. Third, the evaluation origin is offset from the end of the observed history: course staff confirmed that the private test block immediately follows the validation window, so a model conditioned on the last observed target must forecast a horizon beginning 336 steps later — an effective reach of 672 steps. We therefore train and evaluate exclusively at this 336-step gap, and, because the horizon inputs contain no target history and no period-specific labels, we carry only training-derived state (weights, scalers, and the final training window) into the checkpoint rather than baking any validation- or test-period covariates.

Job

3.1 Problem formulation

Define your symbols once, then use them consistently

Let s ∈ {1,…,S} index series with S = 96, and let xs,t ∈ ℝF denote the covariate vector at hour t with F = 22, and ys,t ∈ ℝ the target. Given a lookback window of length L and a forecast origin t0, the model maps the history {(xs,t, ys,t)}t=t0−Lt0−1 together with the known-future covariates {xs,t}t=t0t0+H−1 to the full horizon ŷs,t0:t0+H in a single forward pass, with H = 336.

Say "direct multi-step" explicitly and justify it in one sentence

e.g. "We predict the horizon directly rather than autoregressively, avoiding error accumulation over 336 recursive steps and removing any dependence on predicted covariate values."

3.2 Preprocessing

Three things must appear here, each in two or three sentences: missing-value handling, the two-level normalisation, and windowing.

Normalisation — this is where the exposé was vague

We apply normalisation at two levels. Globally, each covariate is standardised using a mean and standard deviation computed only over training hours, preventing information from the evaluation window entering the fit. Per-window, we apply reversible instance normalisation (RevIN): each input window is centred and scaled by its own statistics, and the inverse transform is applied to the model output. RevIN is intended to absorb distribution shift between the training period and the forecast origin; we note that the cross-series case for it is weak here, as per-series means span only a factor of 2.2, and we therefore treat it as an ablation rather than an assumption.

That last clause is worth a mark on its own

Stating a number that weakens your own design choice, and then testing it instead of asserting it, is exactly the behaviour that separates a report from a write-up. Do this wherever you can.

3.3 Architectures

One short paragraph per model. For PatchTST give the two mechanisms explicitly — patching and channel independence — with the arithmetic, because the arithmetic is the argument.

PatchTST paragraph

PatchTST segments each channel into overlapping patches of length P = 16 with stride 8, reducing our 336-hour window to 41 tokens and the attention cost from 336² to 41², a factor of roughly 67. Each patch is linearly projected to d = 128 and augmented with a learned positional embedding before passing through 3 pre-norm transformer encoder layers with 8 heads. Following Nie et al., channels are processed independently through shared weights: the (B, C, L) input is reshaped to (B·C, L), which multiplies the effective number of training sequences by C and acts as a regulariser, at the cost of forbidding cross-channel attention. We ablate this choice against a channel-mixing variant.

3.4 Objective

Derive the loss from the metric — do not just name it

WAPE is defined as Σ|y − ŷ| / Σ|y|. Because the denominator is constant with respect to the model, WAPE is a fixed rescaling of mean absolute error, and any objective that minimises MAE minimises WAPE. We therefore train with a Huber loss, which is L1-like in the tails but has a smooth gradient near zero; given the target's heavy right tail (median 9.0, maximum 53.0), a squared-error objective would concentrate capacity on rare high-load hours at the expense of aggregate WAPE. We ablate against pure L1 and MSE.

3.5 Evaluation protocol

Rolling-origin, three folds, why. State the fold boundaries as hour indices, and make explicit that every fold is scored at the confirmed 336-step gap so the internal metric matches the graded test rather than the (easier) gap-0 public leaderboard. One sentence should note that the public validation leaderboard measures an immediate-horizon variant and is therefore an optimistic proxy, which is why model selection is done on the internal gap-336 folds. Baselines are scored under the identical gap so the comparison in Table 1 is like-for-like.

4.1 Setup — the reproducibility paragraph

Worked example

All models are trained on 96 series of 4,320 hourly observations (2023-01-01 to 2023-06-29). We evaluate with rolling-origin validation using three folds whose scoring windows are hours [3984, 4320), [3648, 3984) and [3312, 3648); training windows are constrained so that no sample's target overlaps its fold's scoring window. Unless stated otherwise: lookback 336, batch size 16, Adam with learning rate 10⁻³, one-cycle schedule, dropout 0.2, up to 20 epochs with early stopping. 4.4 Discussion — how to write results honestly

Three phrasings you will need. Learn them; they are the difference between confident and overclaiming.

SituationSay thisNot this
Clear effect"Removing the covariate head raises WAPE by 57%, far outside the 0.045 noise floor.""Covariates are crucial."
Effect inside noise"Removing RevIN changes WAPE by −8.3% (0.045 floor); the difference is within seed noise, so we draw no conclusion."Silence, or reporting it as a small win.
The transformer loses"PatchTST does not outperform the LSTM (0.188 vs 0.169). This is consistent with Zeng et al., and plausibly reflects the modest scale of this dataset: 96 series over 180 days."Quietly omitting the comparison.
If PatchTST ties or loses, that is a good report, not a failed project

You are being marked on method and evidence, not on winning. A negative result that is measured carefully, connected to published work, and explained from a dataset property is a stronger submission than a marginal win with no error bars. Say it plainly in the abstract, and the marker will read the rest of the paper as the work of someone who is not fooling themselves.

  • Axis labels with units. Every axis, every time.
